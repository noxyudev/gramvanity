# gramvanity: архитектура

> Язык: [English](architecture.md) | **Русский**

Этот документ описывает раскладку модулей двух программ, владение общим состоянием и контракты
между ними. Он отражает разбиение прежнего 4400-строчного монолита `gramvanity.c` на
сосредоточенные модули (обоснование — в разделе «Решения»).

## Обзор

Один продукт, два сотрудничающих бинарника в одном репозитории:

```text
opencl/gramvanity(.exe)      C + OpenCL: сам поиск (GPU выводит кандидатов, CPU проверяет)
verify-go/w5addr(.exe)       Go: независимый верификатор (JSON-поток stdin) + активатор tg-wallet
```

```text
+--------------------------- opencl/src/ ---------------------------+
| main.c        разбор/проверка CLI, служебные режимы, цикл поиска  |
| platform      переносимость ОС: die/time/CSPRNG/fs/threads/signals |
| options       структура opt, папка задания, usage()               |
| pattern       цели, шаблоны, UTF-8/транслит, сопоставление, шансы  |
| crypto        PBKDF2/SLIP-10/BIP39/TON (Monocypher, sha256.c)     |
| addresses     id W5 v5r1 / WalletTg, friendly(), derive_candidate |
| detsearch     состояние детерминированного поиска (index -> энтропия) |
| gpu           контекст OpenCL, конвейер Job, подбор chunk          |
| stats         счётчики + hit_lock/stat_lock                       |
| checkpoint    текстовый формат checkpoint, восстановление resume  |
| hits          пересчёт, запуск верификатора, hit-файлы, stop-файл |
| search        конвейеры BIP39/TON, учёт диапазонов                |
| selftest      стартовые векторы + unit-тесты --selftest-det       |
| i18n          --lang/GRAMVANITY_LANG, выбор сообщений tr()        |
+-------------------------------------------------------------------+
        |  поток процесса: {"words",mode?,net?} -> {uq,eq,pub,as,...}
        v
+--------- verify-go (один Go-пакет main) -----------+
| main.go       цикл верификатора stdin, режим w5    |
| tgaddress.go  адреса WalletTg, проверка tg         |
| tgkey.go      вывод ключей, сборка подписанного сообщения |
| tonclient.go  HTTP-клиент toncenter v2             |
| tgactivate.go CLI `w5addr activate`                |
+----------------------------------------------------+
```

Правило зависимостей: `main -> {search, hits, checkpoint, selftest, gpu, detsearch, addresses,
crypto, pattern, options, i18n, platform}`, а внутри нижних слоёв — только вниз
(`search -> {gpu, crypto, detsearch, stats, checkpoint, hits}`, `checkpoint -> {pattern, stats,
detsearch, options}`, `hits -> {checkpoint, stats, pattern, crypto, addresses, gpu}`). Циклов нет;
бывший цикл монолита `checkpoint <-> hits` разорван выделенным модулем `stats`. `i18n` — листовой
модуль: он зависит только от libc, поэтому его может подключать любой модуль.

## Замечания по модулям

- **platform** — здесь живут все `#ifdef _WIN32`-разветвления программы (CSPRNG, помощники для
  каталогов и файлов, мьютексы/потоки, обработка сигналов). Обработчику закрытия консоли Windows
  нужно сохранять состояние из своего потока; вместо зависимости от более высокого слоя `main`
  подключает хук `set_emergency_save()` к `save_all_and_report()` — `platform` остаётся листовым
  модулем.
- **pattern** — доменная модель: `Target`/`Pattern`/`StrList`, кодек UTF-8, fallback CP1251 и
  кириллическая транслитерация для id имён файлов, компиляция шаблонов, сопоставление и математика
  вероятностей.
- **stats** — общие счётчики (`total_done`, `hits_found`, `verified`, ...) и две блокировки
  `hit_lock`/`stat_lock`. Модуль существует, чтобы разорвать цикл checkpoint/hits: сериализатор
  checkpoint читает счётчики под `stat_lock`, а обработке хитов нужен `checkpoint_save()`.
- **checkpoint** — владеет текстовым форматом checkpoint (по одному `ключ = значение` на строку,
  секции `[target]`, последняя строка контрольной суммы SHA-256) и восстановлением на стороне resume
  (`job_dir_from_checkpoint`, `resume_apply_target_overrides`, `targets_from_checkpoint`). Писатель
  снимает живое состояние в переиспользуемое хранилище, поэтому записи остаются без выделений памяти
  для обработчика консоли Windows; парсер строг (неизвестные и повторные ключи — ошибки), а
  `checkpoint_fix()` пересчитывает подпись файла после ручной правки.
- **hits** — один хит проходит через `handle_hit` ровно как раньше: фильтрация активных целей
  (`--all-patterns`), пересчёт на CPU, пропуск неоднозначных кошельков, необязательный внешний
  верификатор, запись hit-файла, обновление счётчиков — всё под `hit_lock`. Отчёт конца сессии
  (`write_stop_file`/`save_all_and_report`) идемпотентен через `finish_lock`.
- **search** — два GPU-конвейера. BIP39: одностадийные пакеты с двойной буферизацией. TON:
  стадия 1 (проверка basic-seed, оставляет 1/256) и стадия 2 (`ton_flush`) для выживших. Главный
  цикл напрямую вызывает экспортируемые колбэки потоков
  (`bip_prep_fn`/`bip_post_fn`/`ton_prep_fn`/`ton_post_fn`) для двойной буферизации.
- **gpu** — контекст OpenCL и конвейер `Job` submit/wait/release плюс адаптивный подбор chunk
  (каждый запуск остаётся ~0,25 с, чтобы пережить Windows TDR). Компрессор SHA-512 на CPU (`K512C`)
  живёт здесь как одноразовый помощник для состояний master-key SLIP-10; согласие GPU/CPU
  охраняется стартовым self-test.
- **selftest** — `self_test()` (опубликованные векторы: SHA-256, BIP39 PBKDF2, адреса
  W5/WalletTg, перекрёстные проверки GPU-против-CPU) выполняется перед каждым поиском;
  `--selftest-det` запускает ~50 детерминированных проверок поиска без GPU (именно это запускает
  CI).
- **i18n** — язык сообщений: `--lang en|ru` и `GRAMVANITY_LANG`, по умолчанию английский, без
  автоопределения локали. `tr("english", "русский")` выбирает вариант; в обоих вариантах должны
  совпадать спецификаторы формата printf. Машиночитаемый вывод (теги, ключи, JSON, имена файлов,
  форматная строка checkpoint, поток верификатора) остаётся английским независимо от языка, а
  `w5addr` вообще не принимает `--lang`.

## Владение общим состоянием

У каждого глобального объекта ровно один владеющий модуль, и он экспортируется из его заголовка:

| Состояние | Владелец | Защита |
|---|---|---|
| `opt`, `root_dir`, `job_dir` | options.h | — (только чтение после старта) |
| `targets[]`, `n_targets`, `cur_target`, `g_prefix/g_suffix` | pattern.h | — (финально после старта) |
| `det` (курсоры, ключ поиска) | detsearch.h | формат checkpoint |
| `gpu`, `chunk_iters`, `iter_cost`, `last_iter_time` | gpu.h | — (однопоточная настройка, поток цикла) |
| счётчики, `hit_files[]`, `hit_lock`, `stat_lock` | stats.h | `stat_lock` |
| `g_stop`, `g_finished` | platform.h | семантика обработчика сигналов |
| `checkpoint_lock`, буферы checkpoint | checkpoint.h | `checkpoint_lock` |
| `finish_lock`, `g_stop_path` | hits.h | `finish_lock` |
| `survivors[]`, `n_surv` | search.h | только главный цикл |
| `g_lang` | i18n.h | — (задаётся один раз при старте, дальше только чтение) |

Дисциплина блокировок (не изменилась с монолита, задокументирована здесь): `handle_hit` держит
`hit_lock` всё своё тело и внутри берёт `stat_lock` для обновления счётчиков; `checkpoint_save`
берёт `checkpoint_lock` (и внутри снимка состояния — `stat_lock`); `save_all_and_report` берёт
`finish_lock` (и внутри `write_stop_file` — `stat_lock`). Ни одна блокировка никогда не держится
во время вызовов GPU. Не сужайте эти критические секции без повторного запуска полного набора
`tests/test_det.sh`.

## Контракты

**search <-> verifier (поток процесса).** Поиск запускает `<root>/verify-go/w5addr` (MSYS2 bash на
Windows) и подаёт JSON-строки в stdin:

```text
in:  {"words": "<phrase>", "mode"?: "w5"|"tg", "net"?: "mainnet"|"testnet"}
out: {"uq","eq","pub","as","tonValid","bip39Valid"}          (w5)
     {"uq","eq","pub","as","signpub","bip39Valid","tonValid"} (tg)
```

**Формат checkpoint "gramvanity-checkpoint" v1** (обычный UTF-8-текст, по одному
`ключ = значение` на строку, секции `[target]`, перечисления значений в комментариях в конце строк):
глобальные скаляры (`format`, `version`, `mode`, `bounceable`, `net`, `job_dir`,
`start`/`next`/`s1_next`/`end`, `done`/`unique_hits`/`verified`, `key`), затем для каждой цели
`{name, label, out, count, hits, ignore_case, match, all_patterns, пары suffix/suffix_hits и
prefix/prefix_hits}`. Последняя значащая строка — `checksum = <hex>`: SHA-256 над всеми остальными
строками файла (CR-байты игнорируются), поэтому любое повреждение или ручная правка будут пойманы;
`--checkpoint-fix` проверяет поля и пересчитывает подпись. Значения в кавычках (эскейпы
`\\ \" \n \r \t \xNN`) сохраняют пробелы, кавычки, `#` и произвольные байты; неизвестные и
повторные ключи — ошибки. Файл специально пригоден для правки руками: поднять `count`, поменять
шаблоны, добавить или убрать блок `[target]` — затем `--checkpoint-fix` и `--resume`.

**Детерминированный поиск:** энтропия кандидата =
`HMAC-SHA512(searchKey, "svDET1" || mode || be64 index)`; подписывающая половина tg-wallet
использует отдельный байт режима 16 (`DETSIGN`). Тот же ключ + индекс = тот же кандидат; ключ
живёт только в checkpoint (файл, доступный только владельцу).

## Решения и отступления от исходного плана

1. **stats — отдельный модуль** (в плане он сначала входил в hits): сериализатор checkpoint должен
   читать счётчики под `stat_lock`, а обработка хитов вызывает `checkpoint_save()` — выделение
   stats сохраняет граф зависимостей ацикличным без изменения блокировок.
2. **Парсер CLI остаётся цепочкой strcmp** внутри `parse_args()`, а не становится табличным:
   у опций контекстно-зависимая семантика (глобальные значения по умолчанию против текущего блока
   `--target`) и порядко-зависимые флаги (позиция `--ignore-case` важна); таблица была бы
   переписыванием с риском регрессий без выигрыша в поведении. Теперь цепочка изолирована в одной
   функции.
3. **`Derived` живёт в addresses.h** (в плане он был в sv.h): его создаёт `derive_candidate()`, а
   потребляют main/hits/selftest, поэтому заголовок производителя — его естественный дом; sv.h
   остаётся ограниченным сквозными enum и константами.
4. **`die()` имеет `__attribute__((noreturn))`** — при разделении он стал межмодульным вызовом, и
   аннотация сохраняет и взгляд оптимизатора, и паритет предупреждений со сборкой монолита.
5. Буферы фиксированного размера (`cmd[4400]`, `hit_files[64][300]`, 4 KB буферы путей) намеренно
   оставлены как есть: изменение их размера меняет поведение при ошибках; здесь они
   задокументированы как известные ограничения (`hit_files` ограничивает список файлов
   stop-отчёта 64 на сессию).

## Проверка

- `make -C opencl` — чистая сборка, без новых предупреждений (gcc -Wall -Wextra).
- `opencl/gramvanity --selftest-det` — все unit-проверки проходят (также в CI, GPU не нужен).
- `sh opencl/tests/test_det.sh` — набор сквозных проверок на GPU из 19 сценариев (121 проверок; он
  фиксирует `GRAMVANITY_LANG=en`, потому что проверки сравнивают английский вывод).
- `python3 tools/check_i18n.py` — каждая пара `.md` существует и ссылается на перевод (CI).
- Эталонные запуски: сценарии детерминированного диапазона дают одинаковый вывод `--checkpoint-info` до
  и после рефакторинга (поля, зависящие от ключа, например счётчик «candidates done» у ton-24,
  меняются от запуска к запуску по замыслу, потому что каждый запуск берёт новый случайный ключ
  поиска).
- `go vet ./verify-go && go test ./verify-go` — тесты паритета верификатора фиксируют эталонные
  значения JS-инструмента.
