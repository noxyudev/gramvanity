# Режим Telegram Wallet (`--mode tg-wallet`)

> Язык: [English](tg-wallet.md) | **Русский**

Это руководство объясняет, как работает хит в режиме `tg-wallet`, что означают 24 слова, как
выбрать окончание, как вывести кошелёк на цепь и как импортировать его в Telegram Wallet.

Команды ниже выполняются из папки `opencl/` после `make`; верификатор/активатор —
`../verify-go/w5addr` (`..\verify-go\w5addr.exe` на Windows), а папка задания по умолчанию —
`../results/job-<UTC timestamp>/`.

`tg-wallet` — это `--mode` по умолчанию: поиск, запущенный без `--mode`, ищет адрес Telegram
Wallet. Как и любая цель, он останавливается после первого хита, если `--count N` не просит
больше.

## 1. Что ищется

Telegram Wallet (кошелёк в Telegram, работающий на WalletTg) не использует W5 или вывод
`m/44'/607'/0'` для своего основного кошелька. Его контракт, **WalletTg**, развёрнут за
неизменяемой ячейкой кода **WalletTrampoline**, а адрес — это хеш state init контракта:

```text
code = WalletTrampoline   (JMP на код WalletTg, хранящийся в конфигурации сети)
data = хранилище WalletTg, revision 00:
       revision:u8=0 | seqno:u32=0 | subwallet_id:u32 | public_key:256
```

`subwallet_id` определяет тип кошелька и сеть:

| сеть | subwallet_id | форма адреса |
|---|---|---|
| mainnet | `0x7FFF7F11` | `UQ…` / `EQ…` |
| testnet | `0x7FFF7FFD` | `0Q…` / `kQ…` |

Ячейка кода трамплина заморожена (неизменяема), поэтому каждый адрес Telegram Wallet остаётся
действительным даже при обновлении реализации WalletTg. gramvanity использует хеш кода трамплина
с глубиной 0, поэтому его адреса совпадают с тем, что Telegram Wallet показывает для того же
ключа.

## 2. Как работают 24 слова

Фраза `tg-wallet` — это **две независимые фразы BIP39-12, склеенные вместе**, та же раскладка,
которую Wallet в Telegram использует для своей фразы, поэтому это *не* фраза BIP39-24 (каждая
половина несёт собственную контрольную сумму).

```text
слова  1-12  "якорь"    BIP39-12 -> ключ через m/44'/607'/0' -> публичный ключ в state init
слова 13-24  "подпись"  BIP39-12 -> ключ через m/44'/607'/0' -> ключ, которым подписывает Telegram Wallet
```

- **Слова 1-12 (якорь)** — ключ, с которым контракт *разворачивается*. Это единственная половина,
  влияющая на адрес, поэтому поиск идёт по ней — ровно так же быстро, как `bip39-12`.
- **Слова 13-24 (подпись)** — ключ, на который контракт *переключается* при активации, и ключ,
  которым Telegram Wallet фактически подписывает транзакции. Они вообще не влияют на адрес: один
  и тот же адрес работает с любой подписывающей половиной.

Для обеих половин соблюдаются два свойства:

1. каждая половина должна быть допустимой фразой BIP39-12 (правильная контрольная сумма), чтобы
   кошельки её приняли;
2. ни одна половина не должна быть допустимой как стандартная фраза TON (проверка «basic seed»).
   Иначе кошелёк (Tonkeeper, Wallet) мог бы интерпретировать те же слова иначе. Такие хиты
   пропускаются.

### Детерминированный поиск и подписывающая половина

Поиски детерминированы и возобновляемы по умолчанию (с `--start-offset` их также можно разбивать
на диапазоны). Подписывающая половина хита выводится из того же секретного ключа поиска через
отдельный домен HMAC (`DETSIGN`), поэтому *точные* 24 слова воспроизводимы позже:

```sh
./gramvanity --mode tg-wallet --suffix 'HELLO' --start-offset 0 --tries 100000000 --out ../results/tg-hello
./gramvanity --reveal ../results/tg-hello/job.checkpoint 1234567   # 24 слова, оба ключа, адрес
./gramvanity --mode tg-wallet --derive <key> 1234567         # то же, по ключу из hit-файла
```

Новое задание всегда получает новый случайный ключ поиска, поэтому две одинаковые команды,
запущенные отдельно, ищут разные фразы; продолжайте задание через `--resume` и его checkpoint.

При `--random` подписывающая половина — это свежая случайность, сгенерированная в момент записи
хита, поэтому сохраняйте hit-файл: это единственное место, где она есть (или может быть
восстановлена). Random-режим нельзя возобновить и нельзя сочетать с `--start-offset`, `--tries`,
`--checkpoint` или `--resume`.

## 3. Как выбрать окончание

Адрес TON содержит 48 символов base64url полезной нагрузки; именно последние символы вы ищете.
Стоимость шаблона — произведение множителей, по одному на символ шаблона:

| символ шаблона | множитель стоимости | пример |
|---|---|---|
| литеральный символ | `64` (все 64 символа base64url) | `O` совпадает только с `O` |
| буква в режиме `--ignore-case` | `32` (оба регистра) | `o` совпадает с `o` и `O` |
| класс символов `[abc]` | `64 / k` (k = число символов в классе) | `[a-z_]` ≈ `2.37` |

| окончание | ожидаемое число кандидатов | на одной RTX 4070 Ti Super (~681k/s, `--power 100`) |
|---|---|---|
| `ZQ` | ~4 000 | секунды — хорошо для тестового запуска |
| `HELLO` | ~1,1 млрд (`64^5`) | ~26 мин |
| `[a-z_]HELLO` | ~2,5 млрд (`27 * 64^5`) | ~12 ч |
| шесть фиксированных символов | ~69 млрд | ~1,2 дня |
| семь фиксированных символов | ~4,4 трлн | ~2,5 месяца |

При `--power 65` по умолчанию времена растут примерно на 50%.

Практические правила:

- Стартовая строка `expected ~N phrases until the first hit across all targets` точна для ваших
  шаблонов, а однократная оценка примерно через 4 секунды после старта печатает среднее ожидание
  на цель. Прочитайте её перед запуском, который может длиться долго. Когда у возобновлённого
  задания уже есть цели с заполненным `--count`, строка говорит
  `across the N remaining target(s)` и пропускает их; периодическая строка `% of expected` так же
  отбрасывает завершённые цели, поэтому показанные шансы остаются актуальными.
- Каждый дополнительный символ умножает стоимость до 64 раз. Сначала решите длину, затем точные
  символы. Скобочные шаблоны существуют, чтобы покрыть несколько написаний одной длины
  (`[Hh]ELLO`, `[a-z_]hello`), а не чтобы удешевить поиск — `HELLO` дешевле, чем `[a-z_]HELLO`,
  потому что в `[a-z_]HELLO` на один символ больше.
- Окончания из одного-двух символов — плохая идея для реального кошелька: они настолько дешёвы, что
  атакующий может тривиально найти *другую* фразу с таким же окончанием (address poisoning).
  Обычный минимум — 5+ фиксированных символов, 6-7, если хотите, чтобы окончание было практически
  уникальным.
- Регистр важен: алфавит адреса чувствителен к регистру, поэтому `hello` и `HELLO` — разные
  окончания. `--ignore-case` допускает любой регистр в найденном адресе, что приятнее для глаза,
  но удваивает стоимость на каждую букву — хорошо для длинных читаемых слов.
- Можно запускать несколько заданий параллельно с непересекающимися диапазонами индексов
  (`--start-offset`, `--tries`) и разными checkpoint; каждое задание получает свой случайный ключ
  поиска, поэтому они ищут независимые наборы кандидатов. Хита на любом из них достаточно, после
  чего остальные можно остановить.
- Сначала проверьте всё на **testnet** (`--net testnet`, бесплатный GRAM у
  <https://t.me/testgiver_ton_bot>): весь поток — поиск → активация → импорт — работает там,
  кроме того, что сам Telegram Wallet использует только mainnet.

## 4. Активация (это необычная часть)

Свежий адрес из поиска — это просто хеш: контракт *не развёрнут*, на цепи нет ключа, и ни один
кошелёк — включая Telegram Wallet — пока не может использовать фразу. Создание кошелька означает
отправку одного внешнего сообщения, которое делает всё сразу, точно как приложение Telegram Wallet,
когда создаёт кошелёк:

1. развернуть трамплин + WalletTg с якорным ключом;
2. переключить ключ на подписывающую половину (`ChangePublicKeyRequestE`), подписанную якорным
   ключом;
3. payload переключения ссылается на доказательство, подписанное новым подписывающим ключом,
   поэтому контракт доказывает, что контролирует обе половины.

`verify-go/w5addr activate` (часть Go-верификатора) собирает это сообщение и с `--send`
отправляет его:

```sh
# сначала пополните адрес: 0.05-0.1 TON комфортно, 0.02 TON — минимум, который принимает инструмент
../verify-go/w5addr activate --phrase "w1 … w24" --check    # адрес, состояние на цепи, баланс
../verify-go/w5addr activate --phrase "w1 … w24" --send     # deploy + rotate одним сообщением
../verify-go/w5addr activate --hit ../results/tg-testnet/hit-t1-….txt --send # hit-файл --random: фраза внутри
```

Обычные hit-файлы не содержат фразу; передайте её из `--reveal`:
`./gramvanity --reveal ../results/tg-main/job.checkpoint <index> | ../verify-go/w5addr activate --phrase - --send`.

На Windows используйте `..\verify-go\w5addr.exe`. `--phrase -` читает фразу из stdin, что удобно
для передачи вывода `--reveal` без печати слов.

После `--send` подождите несколько секунд и снова запустите `--check`: он должен сообщить, что
контракт активен, а `on-chain key` равен подписывающему ключу. Это тот же ключ, который Telegram
Wallet выводит из слов 13-24, поэтому фраза теперь — обычная фраза Telegram Wallet.

Примечания:

- Сообщение активации подписано якорным ключом (слова 1-12). После активации якорный ключ мёртв —
  всё равно сохраните его: фраза неделима (24 слова).
- `--net testnet` делает то же самое в testnet; получите testnet GRAM у
  <https://t.me/testgiver_ton_bot>.
- Если у адреса уже есть баланс и правильное состояние (например, вы повторно запустили `--send`),
  инструмент откажется активировать дважды и сообщит, что видит.

## 5. Импорт в Telegram Wallet

1. Убедитесь, что кошелёк активирован (раздел 4) и `--check` показывает подписывающий ключ на цепи.
2. Если на этом аккаунте Telegram уже есть кошелёк, сначала переведите **все** его средства на
   другой доверенный вами адрес: шаги ниже заменяют фразу кошелька.
3. Откройте кошелёк кнопкой **Деньги** в боковой панели Telegram, нажмите **⋮** в верхнем углу и
   выберите **Ключи и резервная копия**.
4. Выберите **Удалить кошелёк**, затем **Добавить существующий**, и введите 24 слова, которые
   нашла программа (точные надписи кнопок зависят от версии Telegram).
5. Кошелёк покажет адрес. Сравните его с тем, что напечатали `gramvanity --reveal` / `--check`:
   совпадать должен символ в символ.
6. Отправьте небольшую тестовую сумму туда и обратно, прежде чем двигать что-то серьёзное.
7. Запишите 24 слова на бумаге (не в «избранное» Telegram), затем удалите папку задания (hit-файлы,
   stop-отчёт и checkpoint): тот, у кого есть ключ поиска из checkpoint, может вывести каждую
   фразу-кандидат задания.

### При желании: смена секретной фразы позже

Делать это не обязательно: gramvanity работает полностью локально, найденная фраза — обычная, и
пользоваться ей безопасно. Это только для тех, кто хочет фразу, выбранную не программой, —
Telegram Wallet умеет заменять фразу существующего кошелька сам:

1. Снова откройте **⋮** → **Ключи и резервная копия** (шаг 3 выше).
2. Выберите **Включить резервное копирование**.
3. Выберите **Отключить резервное копирование** и при подтверждении обязательно отметьте галочку
   **«Сменить секретную фразу»**.
4. Сверьте старую фразу с новой: если последние 12 слов отличаются, всё получилось. Адрес не
   меняется (первые 12 слов те же), но старая подписывающая половина перестаёт подписывать за
   кошелёк — дальше храните в безопасности новую фразу вместо старой.
5. Новую секретную фразу никому не передавайте никогда: Telegram создаёт её на устройстве и
   никуда не отправляет.

## 6. Соображения о стоимости

- Активация стоит обычную комиссию за внешнее сообщение (несколько сотых TON, включая минимальный
  баланс 0.02 TON, который нужно оставить на свежем аккаунте).
- Развёрнутый кошелёк — это обычный контракт WalletTg; аренда его хранилища покрывается обычным
  образом, когда на кошельке есть небольшой баланс.
- Vanity-окончание = повышение входной цены для атак address poisoning: атакующему, который хочет
  обмануть вас, отправив с похожего адреса, придётся самому заплатить за такое же окончание, и
  цена растёт с числом закреплённых символов.

## 7. Быстрый рецепт

```sh
# 1. эксперимент в testnet (бесплатно, быстро, одноразово: --random хранит фразу в hit-файле)
./gramvanity --mode tg-wallet --net testnet --suffix ZQ --random --out ../results/tg-testnet
../verify-go/w5addr activate --hit ../results/tg-testnet/hit-t1-*.txt --net testnet --check
# пополните с https://t.me/testgiver_ton_bot, затем:
../verify-go/w5addr activate --hit ../results/tg-testnet/hit-t1-*.txt --net testnet --send

# 2. mainnet, большой ограниченный диапазон (детерминированно и возобновляемо по умолчанию)
./gramvanity --mode tg-wallet --suffix '[a-z_]HELLO' --start-offset 0 \
             --tries 100000000000 --out ../results/tg-main
#    (Ctrl+C в любой момент; checkpoint — ../results/tg-main/job.checkpoint; продолжить позже:)
./gramvanity --resume ../results/tg-main/job.checkpoint

# 3. после хита: восстановить 24 слова, активировать, импортировать
./gramvanity --reveal ../results/tg-main/job.checkpoint <index>  # или команда --derive из hit-файла
../verify-go/w5addr activate --phrase "<24 words>" --check
../verify-go/w5addr activate --phrase "<24 words>" --send
```
