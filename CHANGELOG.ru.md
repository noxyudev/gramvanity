# Журнал изменений

> Язык: **Русский** | [English](CHANGELOG.md)

Все значимые изменения gramvanity документируются здесь.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/); версии — по
[SemVer](https://semver.org/).

## [1.2.1] - 2026-11-15

Патч-релиз: установка в одну команду работает, оба установщика запрашивают папку установки, и
установку снова можно удалить.

### Добавлено
- Пользовательские деинсталляторы внутри релиза (`tools/uninstall.ps1`, `tools/uninstall.sh`):
  удаляют программные файлы и сохраняют `results/`, checkpoints и hit-файлы, если не задан
  `--full` / `-Full` с подтверждением вводом `yes`. Деинсталлятор отказывается работать с папками
  без маркеров gramvanity (`opencl/gramvanity`, `verify-go/w5addr`), не трогает ничего за
  пределами папки установки и не требует сети.

### Исправлено
- Задокументированная установка в одну команду для Windows (`irm ... | iex`) вообще не могла
  выполниться: скрипт хранится в UTF-8 с BOM, `Invoke-RestMethod` возвращает этот BOM как символ,
  и парсер PowerShell отвергает `param`-блок после него. Быстрый вариант теперь —
  `& ([scriptblock]::Create((irm <url>).TrimStart([char]0xFEFF)))`, что работает в Windows
  PowerShell 5.1 и может принимать параметры.
- install-user.sh сообщал «GPU: готов к поиску», даже когда установленный бинарник вообще не мог
  стартовать (например, libOpenCL.so.1 отсутствует на сервере без драйверов GPU): проверка
  готовности игнорировала код возврата, а текст ошибки загрузчика терялся из вывода. Теперь
  проверка требует код 0, ошибка загрузчика остаётся видимой, а отсутствие загрузчика OpenCL
  получает отдельное объяснение с именем apt-пакета.

### Изменено
- `install-user.ps1` и `install-user.sh` больше не молча выбирают `%LOCALAPPDATA%\gramvanity` /
  `~/.local/opt/gramvanity`: оба запрашивают папку установки, молчаливого значения по умолчанию
  нет. Раскрываются `~`, `%VAR%` и `$env:VAR` (Windows) или ведущий `~` (Linux), относительные
  пути работают, корневые папки запрещены. `-InstallDir <путь>` / `--install-dir <путь>` отвечают
  на запрос из командной строки и нужны для запусков без участия человека и для `--dry-run` без
  интерактивной консоли.

## [1.2.0] - 2026-11-15

Релиз установки и удобства разработчика: проверенный установщик в одну команду для игроков,
настройка окружения разработчика без сюрпризов (нативно или через Docker) и закалка
`w5addr activate`. Релизные архивы теперь проверяются в CI до публикации.

### Добавлено
- Пользовательские установщики в одну команду (`tools/install-user.ps1`, `tools/install-user.sh`):
  скачивают готовый релиз, проверяют его SHA-256 и устанавливают в
  `%LOCALAPPDATA%\gramvanity` / `~/.local/opt/gramvanity` без прав администратора, выполняют
  `--selftest-det` и `--list-devices` и никогда не трогают существующий `results/`. Конкретный
  релиз выбирается через `--version`, а `--dry-run` печатает план действий, ничего не меняя.
  Драйвер GPU автоматически не устанавливается никогда; при отсутствии GPU с OpenCL установщик
  выводит инструкции для конкретного производителя.
- Настройка окружения разработчика одной командой после клонирования: `tools/setup-dev.ps1` плюс
  `tools/setup-dev-msys2.sh` (Windows, MSYS2 UCRT64) и `tools/setup-dev-linux.sh`
  (Ubuntu/Debian). Ставятся только недостающие компоненты, а существующий Go никогда не
  обновляется: переносимый распаковывается в `%LOCALAPPDATA%\gramvanity-dev` /
  `~/.local/gramvanity-dev` и подключается только сессионным PATH, так что глобальный PATH
  остаётся неизменным. Полностью настроенная машина проходит setup без единой установки.
  На Linux `--with-gpu-tests` добавляет benchmark и полный интеграционный GPU-набор.
- Контейнерная среда сборки (`docker/Dockerfile`): сборка и CPU-проверки в контейнере без
  установки MSYS2, Go, Python или GCC на хост. Репозиторий монтируется, поэтому бинарники
  остаются на хосте в ожидаемой раскладке `opencl/` + `verify-go/`; GPU доступен только на
  Linux-хостах (`--device /dev/dri` или nvidia-container-toolkit).
- Релизный workflow теперь распаковывает каждый собранный архив, проверяет ожидаемую раскладку
  файлов, запускает `w5addr activate --help` и (на Linux) `--selftest-det` из архива до
  публикации.

### Изменено
- `make -C opencl embed` использует настраиваемую переменную `PYTHON` (по умолчанию `python3`);
  если доступен только `python`, запускайте `make embed PYTHON=python`.

### Исправлено
- `w5addr activate` сообщает об ошибке вместо фиктивного «balance 0 GRAM», когда toncenter
  возвращает неразбираемый баланс.
- `w5addr activate` отказывается продолжать, когда состояние аккаунта `active`, но toncenter не
  вернул код контракта: нельзя убедиться, что адрес — Telegram Wallet (fail-closed; пустой код
  для `uninitialized` остаётся ожидаемым).
- `w5addr activate --valid-for` ограничен диапазоном 1..604800 секунд (7 суток) вместо
  молчаливого принятия значений, способных переполнить окно действия сообщения.

## [1.1.3] - 2026-11-15

### Исправлено
- Префиксы, первый символ которых невозможен после тега формы, отклоняются на старте; ожидание префиксов теперь использует корректный домен из четырёх первых символов вместо 64.
- Ошибочные параметры запуска, шаблоны, объединение checkpoint и GPU self-test больше не оставляют пустых папок заданий. Неудачная атомарная запись удаляет временный файл, а успешный детерминированный self-test удаляет свою пустую папку.
- `--net testnet` отклоняется до настройки команды, если режим не восстанавливается из checkpoint resume.

## [1.1.2] - 2026-11-08

Релиз корректности и защиты: аварийное сохранение Windows, диагностика
возобновляемости и путь к верификатору теперь работают как задокументировано,
а секретные файлы получают ACL «только владелец» на Windows.

### Исправлено
- Аварийное сохранение при закрытии консоли Windows снова подключено: закрытие
  окна посреди батча сохраняет checkpoint и пишет stop-отчёт из потока
  обработчика вместо потери всего с последнего автосохранения.
- `--resume --tries` отвергает конец, оказавшийся позади незакоммиченной
  границы стадии 1 задания ton-24 (после сбоя она достигает миллионов
  индексов). Раньше принятый случай искал за пределами конца, засчитывал хиты
  и откатывал checkpoint, поэтому следующее расширение дублировало hit-файлы и
  счётчики; продолжайте с большим `--tries` или без него.
- Неудавшиеся записи checkpoint сообщаются - одна строка stderr за интервал
  автосохранения и явная итоговая строка о неудаче вместо «checkpoint saved» -
  вместо молчаливого игнорирования.
- При запуске из любого рабочего каталога бинарник снова находит верификатор и
  папку `results/` по умолчанию относительно своего расположения: `exe_dir`
  неверно обрабатывал путь с обратными слешами от `GetModuleFileNameA`, поэтому
  вне `opencl/` верификатор сообщал «not runnable», а папки заданий появлялись
  рядом с рабочим каталогом.
- Временный файл верификатора называется по pid, поэтому два параллельных
  запуска не могут прочитать ответ друг друга.
- Бинарный checkpoint 1.0.x называется как таковой в ошибке загрузки вместо
  общего сообщения про чужой файл.
- `make -C opencl` выбирает Windows-ветку и по uname, а не только по переменной
  OS: обычный make в чистой оболочке MSYS2 больше не падает с «undefined
  reference to BCryptGenRandom».

### Безопасность
- На Windows checkpoint'ы, hit-файлы, stop-отчёты и создаваемые папки заданий
  получают защищённый ACL «только владелец» (POSIX уже создавал их 0600/0700);
  другие локальные пользователи больше не могут прочитать ключ поиска из
  общего каталога.

### Добавлено
- `tools/check_tr.py` с шагом в CI: каждая пара `tr()` обязана нести одни и те
  же printf-спецификаторы (проверено 221 пара).
- Сценарии GPU-набора: bip39-24 от начала до конца, запуск из чужого рабочего
  каталога, сообщение о неудавшейся записи checkpoint и отказ на границе
  стадии 1 ton-24.

## [1.1.1] - 2026-11-08

### Добавлено

- Новая команда `--checkpoint-merge --in CKPT [--in CKPT...] [--out DIR]`: пересобирает один или
  несколько checkpoint в новый, содержащий только цели, ещё не добравшие свой `--count`. Каждый
  `--in` — файл checkpoint или папка задания; объединённый файл записывается как `job.checkpoint`
  в новой папке задания (`--out DIR`, по умолчанию `results/job-<UTC-метка>`). Выполненные цели
  отбрасываются — их хиты остаются восстановимыми только из исходных checkpoint (`--reveal` там);
  одна и та же цель в нескольких входах склеивается по максимуму полей; повторно использованное
  имя с другими шаблонами получает суффикс `-2`, `-3`... Результат — новое задание: свежий ключ
  поиска, позиция начинается с индекса 0, счётчики задания обнулены; объединённый файл не хранит
  `job_dir`, поэтому его собственная папка и есть папка задания при продолжении.
- Писатель checkpoint не пишет пустые строки `job_dir` и `out` (на этом основано слияние;
  `--checkpoint-fix` убирает их и в файлах, собранных вручную).

## [1.1.0] - 2026-11-08

Файл checkpoint становится пригодным для ручного редактирования UTF-8-текстом:
правьте его в любом редакторе и переподписывайте через `--checkpoint-fix`.

### Изменено

- **BREAKING**: файл checkpoint теперь — пригодный для правки руками UTF-8-текст
  ("gramvanity-checkpoint" v1): по одному `ключ = значение` на строку, секции `[target]`,
  перечисления значений в комментариях в конце строк и последняя строка `checksum` (SHA-256 над
  всеми остальными строками). Старый бинарный формат удалён полностью: старые `.ckpt`-файлы не
  читаются, вместо продолжения задания нужно начать новое. Бинарники 1.0.x не читают новые файлы.
- Новая команда `--checkpoint-fix FILE`: проверяет отредактированный вручную checkpoint (все поля,
  кроме контрольной суммы) и перезаписывает его с новой суммой; `--resume` отказывается читать
  файл, чья сумма не сходится. Типичные правки: поднять `count` цели, поменять шаблоны, добавить
  или убрать блок `[target]`, сбросить диапазон (см. раздел про checkpoint в README).
- `--ckpt-info` переименован в `--checkpoint-info` (вывод тот же); имя checkpoint-файла по
  умолчанию — `job.checkpoint`.
- Биты флагов цели перенумерованы (глобальные: бит0 bounceable, бит1 testnet; цели: ignore-case,
  задан count, `--match or`, `--all-patterns`), мёртвое поле `legacy_or` удалено вместе с
  читателями legacy-checkpoint. Наблюдаемого изменения поведения для новых заданий нет.

## [1.0.2] - 2026-11-07

### Добавлено

- Руководство по процессу выпуска (`docs/release-process.md` / `docs/release-process.ru.md`):
  версионирование, правила коммитов и журнала изменений, чек-лист выпуска, работа workflow
  `release`, шаблон release notes и известные ограничения; пара проверяется
  `tools/check_i18n.py`.

### Изменено

- Сопоставление адреса в `finish()` свёрнуто в два точных битсет-NFA (префиксы заякорены после
  тега формы, окончания — к последнему символу адреса) вместо перебора целей по одной; результат
  идентичен, CPU-пост-фаза быстрее при большом числе целей. `GRAMVANITY_MATCHER_CHECK=1` сверяет
  быстрый матчер с перебором целей.

## [1.0.0] - 2026-11-06

Первый релиз форка. gramvanity вырос из
[necrovolt/seedvanity](https://github.com/necrovolt/seedvanity) и сохраняет ту же
идею: поиск ведётся по настоящим сид-фразам, поэтому найденный адрес — тот,
который кошелёк показывает при импорте. Глобальные изменения относительно
оригинального проекта:

### Движок поиска

- Монолитный `opencl/seedvanity.c` переписан в модульное дерево `opencl/src/`.
- Вывод публичного ключа Ed25519 выполняется на GPU (`opencl/ed25519_gpu.cl`) —
  снимается узкое место на CPU для дискретных GPU; для независимой CPU-проверки
  каждого хита вендорится ed25519-donna.

### Процесс поиска

- Один запуск ищет несколько адресов сразу, у каждого свои паттерны, лимиты и вывод.
- Все файлы прогона лежат в одной job-папке (хиты, стоп-отчёт, чекпоинт).
- Формат чекпоинта хранит эти цели; чекпоинты старых версий продолжают загружаться.
- Hit-файлы перечисляют все совпавшие цели (`hit-A+B-<index>.txt`).

### Кошельки

- Поддержка Telegram Wallet (WalletTg): специальные 24-словные фразы и однократная
  активация через `w5addr activate`; `--mode tg-wallet` — режим по умолчанию.
- Верификатор переписан с Node.js на Go (`verify-go/`): независимый пересчёт хитов
  на tonutils-go плюс команда активации.

### Платформы и сборка

- Сборка macOS/Metal удалена; поддерживаются Linux и Windows через OpenCL.
- Единый скрипт сборки Windows (`build-windows.sh`, MSYS2 UCRT64).

### Качество и документация

- GPU-набор `opencl/tests/test_det.sh` (20 сценариев, 113 проверок) и `--selftest-det`
  (~50 CPU-ассертов).
- CI на GitHub Actions (Linux + Windows) и релизы по тегу с готовыми архивами.
- Двуязычная документация (английский/русский) и локализация `--lang en|ru`.
