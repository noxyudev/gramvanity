## [1.1.0] - 2026-11-08

Файл checkpoint становится пригодным для ручного редактирования UTF-8-текстом:
правьте его в любом редакторе и переподписывайте через `--checkpoint-fix`.

### Изменено

- **BREAKING**: файл checkpoint теперь — пригодный для правки руками UTF-8-текст
  ("gramvanity-checkpoint" v1): по одному `ключ = значение` на строку, секции `[target]`,
  перечисления значений в комментариях в конце строк и последняя строка `checksum` (SHA-256 над
  всеми остальными строками). Старый бинарный формат удалён полностью: старые `.ckpt`-файлы не
  читаются, вместо продолжения задания нужно начать новое. Бинарники 1.0.x не читают новые файлы.
- Новая команда `--checkpoint-fix FILE`: проверяет отредактированный вручную checkpoint (все поля,
  кроме контрольной суммы) и перезаписывает его с новой суммой; `--resume` отказывается читать
  файл, чья сумма не сходится. Типичные правки: поднять `count` цели, поменять шаблоны, добавить
  или убрать блок `[target]`, сбросить диапазон (см. раздел про checkpoint в README).
- `--ckpt-info` переименован в `--checkpoint-info` (вывод тот же); имя checkpoint-файла по
  умолчанию — `job.checkpoint`.
- Биты флагов цели перенумерованы (глобальные: бит0 bounceable, бит1 testnet; цели: ignore-case,
  задан count, `--match or`, `--all-patterns`), мёртвое поле `legacy_or` удалено вместе с
  читателями legacy-checkpoint. Наблюдаемого изменения поведения для новых заданий нет.

## [1.0.2] - 2026-11-07

### Добавлено

- Руководство по процессу выпуска (`docs/release-process.md` / `docs/release-process.ru.md`):
  версионирование, правила коммитов и журнала изменений, чек-лист выпуска, работа workflow
  `release`, шаблон release notes и известные ограничения; пара проверяется
  `tools/check_i18n.py`.

### Изменено

- Сопоставление адреса в `finish()` свёрнуто в два точных битсет-NFA (префиксы заякорены после
  тега формы, окончания — к последнему символу адреса) вместо перебора целей по одной; результат
  идентичен, CPU-пост-фаза быстрее при большом числе целей. `GRAMVANITY_MATCHER_CHECK=1` сверяет
  быстрый матчер с перебором целей.

## [1.0.0] - 2026-11-06

Первый релиз форка. gramvanity вырос из
[necrovolt/seedvanity](https://github.com/necrovolt/seedvanity) и сохраняет ту же
идею: поиск ведётся по настоящим сид-фразам, поэтому найденный адрес — тот,
который кошелёк показывает при импорте. Глобальные изменения относительно
оригинального проекта:

### Движок поиска

- Монолитный `opencl/seedvanity.c` переписан в модульное дерево `opencl/src/`.
- Вывод публичного ключа Ed25519 выполняется на GPU (`opencl/ed25519_gpu.cl`) —
  снимается узкое место на CPU для дискретных GPU; для независимой CPU-проверки
  каждого хита вендорится ed25519-donna.

### Процесс поиска

- Один запуск ищет несколько адресов сразу, у каждого свои паттерны, лимиты и вывод.
- Все файлы прогона лежат в одной job-папке (хиты, стоп-отчёт, чекпоинт).
- Формат чекпоинта хранит эти цели; чекпоинты старых версий продолжают загружаться.
- Hit-файлы перечисляют все совпавшие цели (`hit-A+B-<index>.txt`).

### Кошельки

- Поддержка Telegram Wallet (WalletTg): специальные 24-словные фразы и однократная
  активация через `w5addr activate`; `--mode tg-wallet` — режим по умолчанию.
- Верификатор переписан с Node.js на Go (`verify-go/`): независимый пересчёт хитов
  на tonutils-go плюс команда активации.

### Платформы и сборка

- Сборка macOS/Metal удалена; поддерживаются Linux и Windows через OpenCL.
- Единый скрипт сборки Windows (`build-windows.sh`, MSYS2 UCRT64).

### Качество и документация

- GPU-набор `opencl/tests/test_det.sh` (20 сценариев, 113 проверок) и `--selftest-det`
  (~50 CPU-ассертов).
- CI на GitHub Actions (Linux + Windows) и релизы по тегу с готовыми архивами.
- Двуязычная документация (английский/русский) и локализация `--lang en|ru`.
