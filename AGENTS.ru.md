# AGENTS.md — gramvanity

> Язык: [English](AGENTS.md) | **Русский**

## 1. Назначение и структура

`gramvanity` ищет seed-фразы, дающие заданный vanity-адрес TON/GRAM. Тяжёлая часть (PBKDF2,
SLIP-10, Ed25519) считается на GPU через OpenCL; проверка адресов, перепроверка хитов и
независимый верификатор — на CPU/Go.

| Путь | Назначение |
|---|---|
| `opencl/` | основная программа: C host (`opencl/src/`), OpenCL-ядра (`kernel.cl`, `ed25519_gpu.cl`), `embedded.h`, `Makefile`, `tests/` |
| `verify-go/` | независимый верификатор на tonutils-go и подкоманда `w5addr activate` для tg-wallet |
| `docs/` | `architecture.md` (карта модулей и блокировки), `tg-wallet.md` и их русские пары |
| `.github/workflows/` | CI (Linux + Windows) и сборка релизов |
| `results/` | рабочие данные запусков; содержит секреты и в Git не попадает |

Поддерживаются Linux (x86_64, arm64) и Windows (x86_64). Основная локальная среда Windows —
MSYS2 UCRT64.

Перед изменениями прочитай:
- `README.md` — пользовательское поведение и CLI;
- `docs/architecture.md` — модули, владение состоянием и дисциплина блокировок;
- для `opencl/` — `opencl/README.md`, `opencl/AGENTS.md` и `Makefile`;
- исходники и тесты, которых касается задача. Не угадывай структуру проекта.

## 2. Документация и локализация

Основной язык пользовательской документации, инструкций для агентов и комментариев в исходниках —
английский. Русские копии используют суффикс `.ru.md`:

- `README.md` / `README.ru.md`;
- `opencl/README.md` / `opencl/README.ru.md`;
- `AGENTS.md` / `AGENTS.ru.md`;
- `opencl/AGENTS.md` / `opencl/AGENTS.ru.md`;
- `docs/architecture.md` / `docs/architecture.ru.md`;
- `docs/tg-wallet.md` / `docs/tg-wallet.ru.md`;
- `CHANGELOG.md` / `CHANGELOG.ru.md`.

В начале каждой пары есть ссылка на другой язык. Меняя одну версию, обновляй вторую в том же
изменении. `tools/check_i18n.py` проверяет наличие всех пар и взаимные ссылки; CI запускает эту
проверку на Linux.

Правила локализации во время выполнения:

- `gramvanity` принимает `--lang en|ru` и переменную окружения `GRAMVANITY_LANG`. По умолчанию —
  английский; автоопределения локали нет.
- `verify-go/w5addr` остаётся на английском: это верификатор/активатор, его вывод читают скрипты.
- Понятный человеку текст в hit-, stop- и отчётных файлах пишется на языке запуска. Машиночитаемые
  ключи и теги (`HIT`, `target`, `index`, JSON-ключи), флаги CLI, magic-строки checkpoint, имена
  файлов и протокольные строки остаются английскими.
- Комментарии в исходниках оформляются явными блоками `EN:` / `RU:` для содержательных
  комментариев. Тривиальные однострочные комментарии и идентификаторы не переводятся.

Не переводи `third_party/`, сгенерированный `opencl/embedded.h`, `go.sum`, бинарники, `LICENSE` и
`NOTICE`.

## 3. Окружение Windows

Используй MSYS2 UCRT64. Ожидаемые значения:

```bash
printf 'MSYSTEM=%s\nOS=%s\nMINGW_PREFIX=%s\n' "${MSYSTEM:-}" "${OS:-}" "${MINGW_PREFIX:-}"
gcc -dumpmachine
command -v gcc make go
```

- `MSYSTEM=UCRT64`;
- `OS=Windows_NT`;
- `MINGW_PREFIX=/ucrt64`;
- GCC target `x86_64-w64-mingw32`;
- GCC, make, OpenCL headers/ICD loader, Go; Python 3 — только для `make embed`.

Go может отсутствовать в PATH UCRT64; `build-windows.sh` автоматически ищет его в
`C:\Program Files\Go\bin`.

Не заменяй UCRT64 на MINGW64, MSYS, Git Bash или WSL. Не переустанавливай уже установленные
инструменты без конкретной причины. Не меняй глобальный Windows PATH и не смешивай библиотеки
разных сред MSYS2.

Если агент работает в облачной среде или контейнере, не считай, что у него есть MSYS2 и GPU
пользователя: сначала определи, где фактически выполняется команда.

## 4. Сборка

Полная сборка Windows — единый сценарий из корня:

```bash
bash ./build-windows.sh
bash ./build-windows.sh --clean     # удалить старые бинарники и собрать заново
bash ./build-windows.sh --check     # сборка + selftest-det + go vet/test
```

Сценарий проверяет окружение и инструменты, собирает `verify-go/w5addr.exe`, затем
`opencl/gramvanity.exe`, обрабатывает документированный fallback при `BCryptGenRandom` и
проверяет наличие обоих файлов. Сообщения сценария поддерживают `--lang en|ru` и
`GRAMVANITY_LANG`; по умолчанию — английский.

Для точечных изменений:

```bash
make -C opencl
go build -o verify-go/w5addr.exe ./verify-go
```

Linux:

```bash
make -C opencl
go build -o verify-go/w5addr ./verify-go
```

Не дублируй вручную всю последовательность, если `build-windows.sh` работает. Если сборка
завершилась ошибкой: прочитай полный вывод, определи этап, проверь окружение и зависимости,
исправляй конкретную причину. Не объявляй сборку успешной, пока не проверил выходные файлы.

## 5. Структура сборки

Сохраняй раскладку:

```text
gramvanity/
├── opencl/
│   └── gramvanity.exe
└── verify-go/
    └── w5addr.exe
```

Поиск ищет верификатор относительно `opencl/` (`../verify-go/w5addr[.exe]`) и пишет результаты
в `../results/`. Не перемещай бинарники по отдельности и не меняй эту раскладку. Бинарники
игнорируются Git — не коммить их.

Go-верификатор нужен для доверенной проверки хитов и активации tg-wallet. Без него результаты со
статусом `unverified` нельзя считать проверенными.

## 6. Генерируемые файлы

`opencl/embedded.h` генерируется из `kernel.cl`, `ed25519_gpu.cl`, `sha512_consts.h`,
`english.txt` и хранится в репозитории. Сборка читает только `embedded.h`, а не исходные ядра.

После правки любого из этих файлов:

```bash
make -C opencl embed
```

Нужен Python 3. Цель Makefile вызывает `python3`; если в окружении есть только `python`,
запусти `python opencl/tools/embed.py` из корня. Исходники ядер — в UTF-8, и их двуязычные
комментарии попадают в `embedded.h` дословно, поэтому правка только комментария всё равно требует
перегенерации. Проверь diff `embedded.h` и включи его в изменения. Не редактируй `embedded.h`
вручную. Подробности — в `opencl/AGENTS.md`.

## 7. Безопасность

`results/`, checkpoints, hit- и stop-файлы, а также `--dump` могут содержать seed-фразы и
секретный search key.

- Не публикуй содержимое этих файлов и не открывай его без необходимости для задачи.
- Не добавляй `results/` в Git.
- Не отправляй checkpoints и фразы во внешние сервисы и облачные AI-агенты.
- Не включай секреты в логи, отчёты, примеры и тестовые фикстуры.
- Тестовые фразы в коде и тестах — публичные throwaway-фразы; никогда не отправляй на них средства.

## 8. Проверки

Минимум после изменений в C/OpenCL:

```bash
./opencl/gramvanity.exe --selftest-det
```

`--selftest-det` не требует GPU (~50 детерминированных проверок), но не заменяет проверку
GPU-вычислений.

После изменений в Go-верификаторе:

```bash
go vet ./verify-go
go test -count=1 ./verify-go
```

После изменений в документации и локализации:

```bash
python3 tools/check_i18n.py
```

GPU-проверки, если задача их затрагивает:

```bash
./opencl/gramvanity.exe --list-devices
./opencl/gramvanity.exe --mode bip39-12 --bench 60
sh opencl/tests/test_det.sh
```

`test_det.sh` — интеграционный набор на GPU (20 сценариев, 113 проверок, около 7 минут).
Запускай его из корня или из `opencl/`: скрипт сам переходит в нужный каталог и использует
временные папки. Без GPU этот набор выполнить нельзя — явно сообщи об этом в итоговом отчёте.

CI (`.github/workflows/ci.yml`) собирает Linux и Windows, запускает `--selftest-det` на Linux,
`go vet`/`go test` и проверку пар документации. GPU-набор остаётся локальной проверкой. Не ломай
этот контракт.

При `SELF-TEST FAILED` не запускай поиск на этом устройстве до выяснения причины. Успешная
компиляция не доказывает корректность вычислений.

## 9. Правила работы агента

- Изучай текущую реализацию и связанные тесты до изменений.
- Не переписывай работающие компоненты без необходимости; изменения делай минимальными и локальными.
- Не удаляй пользовательские `results/`, checkpoints и конфигурации.
- Не меняй формат checkpoint, hit- и stop-файлов без явной необходимости и проверки совместимости.
- Не удаляй и не ослабляй проверки и тесты ради прохождения.
- Не запускай длинный поиск ради проверки; используй `--bench`, ограниченные `--tries` и `--selftest-det`.
- Для изменений в `opencl/` дополнительно соблюдай `opencl/AGENTS.md`.
- В итоговом сообщении перечисляй изменённые файлы, выполненные команды, результаты проверок и
  оставшиеся проблемы.
