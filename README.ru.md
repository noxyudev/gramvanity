# gramvanity

> Язык: [English](README.md) | **Русский**

**Выбирайте, как выглядит адрес вашего кошелька TON, — и получайте настоящую seed-фразу, которая
его создаёт.**

Адрес кошелька обычно выглядит как случайная строка вроде `UQAbC…7xQ2`. gramvanity ищет
seed-фразу, адрес которой заканчивается на выбранное вами: `HELLO`, `777`, ваш ник. Когда он
находит такую, вы импортируете фразу в обычный кошелёк — **Tonkeeper**, **My Wallet** или
**Telegram Wallet** — выбираете кошелёк W5, и кошелёк показывает именно этот адрес. Ничего не
подделано и не обёрнуто: это обычная seed-фраза с обычным адресом.

Поиск выполняется на видеокарте, поэтому окончание из четырёх-пяти символов занимает от секунд до
примерно часа при настройке мощности по умолчанию — не недели.

**Адреса Telegram Wallet используются по умолчанию** (`--mode tg-wallet`). Для них нужна
специальная фраза из 24 слов и один онлайн-шаг (активация), прежде чем кошелёк можно будет
импортировать. Другие форматы выбираются через `--mode`: `bip39-12` или `bip39-24` для Tonkeeper
и My Wallet, `ton-24` для стандартной мнемоники TON. Руководство по Telegram Wallet:
[docs/tg-wallet.ru.md](docs/tg-wallet.ru.md).

Канал проекта: **[t.me/gramvanity](https://t.me/gramvanity)**.

## Откуда взялся проект

- **Оригинальный проект:** [necrovolt/seedvanity](https://github.com/necrovolt/seedvanity), создан
  [miutalk](https://t.me/miutalk) и [Vibes 18+](https://t.me/vibes).
- **Этот форк:** поддерживается **[нокси](https://t.me/pauper)**.

Форк сохраняет ту же идею и тот же поисковый движок и меняет то, что мешает реальному
использованию:

- сборка для macOS удалена — осталась только сборка с OpenCL, для Linux и Windows;
- один запуск может искать **несколько адресов одновременно**, у каждого свои шаблоны, лимиты и
  папка вывода;
- каждый запуск хранит все свои файлы в **одной папке задания** (хиты, stop-отчёт, checkpoint);
- checkpoint — редактируемый руками текстовый файл, хранящий эти цели; откройте его в любом
  редакторе и после правки переподпишите через `--checkpoint-fix`;
- hit-файлы называют все цели, которым соответствует найденный адрес
  (`hit-A+B-<index>.txt`).

## Почему не обёртка для майнинга?

Есть другой известный подход: [ton-org/vanity](https://github.com/ton-org/vanity) подбирает соль
для контракта-обёртки, привязанного к адресу владельца. Это очень быстро, но результат — контракт,
а не ваш кошелёк. Если импортировать seed-фразу в кошелёк, кошелёк вычислит стандартный адрес из
ключа и не покажет подобранный контракт.

gramvanity делает более медленную, но честную вещь: он ищет по самим seed-фразам. Что бы ни
вычислил кошелёк при импорте, это и будет ваш адрес. Цена — полный вывод ключа для каждого
кандидата, что как раз хорошо ложится на GPU.

## Как это работает, простыми словами

1. Программа придумывает случайную seed-фразу, как это сделал бы кошелёк.
2. Она превращает фразу в приватный ключ, затем в публичный ключ — так же, как Tonkeeper и
   My Wallet делают при импорте.
3. Она строит адрес кошелька из этого ключа.
4. Она сравнивает адрес с вашим шаблоном. Если адрес подходит, фраза (или ключ поиска и индекс,
   которые её воссоздают) сохраняется.
5. Если нет, программа выбрасывает фразу и пробует следующую.

Шаги 2–4 занимают несколько микросекунд или меньше на GPU, поэтому программа может пробовать сотни
тысяч фраз в секунду. Каждый хит затем пересчитывается на CPU и, если верификатор установлен,
проверяется независимой реализацией tonutils-go, прежде чем о нём сообщат.

## Что нужно

- GPU с поддержкой OpenCL 1.2: NVIDIA, AMD или Intel. Драйвер, который вы уже используете для игр
  или графики, обычно включает OpenCL.
- Linux (x86_64 или arm64) или Windows (x86_64).
- Для запуска готовой сборки больше ничего не нужно: ни Node.js, ни Go, ни Python, ни компилятора.

Самому поиску не нужны ни узел TON, ни интернет, ни аккаунт. Всё работает локально.

## Установка

### Готовые бинарники (рекомендуется)

Скачайте архив для вашей системы со страницы релизов и распакуйте его. Релиз сохраняет раскладку
репозитория, потому что поиск ищет верификатор и пишет `results/` на уровень выше своей папки:

```text
opencl/gramvanity        # или opencl/gramvanity.exe — сам поиск
verify-go/w5addr         # или verify-go/w5addr.exe — независимый верификатор / активатор tg-wallet
```

Распакуйте куда угодно, перейдите в `opencl` и запустите `./gramvanity` (Windows:
`.\gramvanity.exe`). Не разносите два файла по разным местам и держите папки `opencl/` и
`verify-go/` рядом. Установка не требуется.

### Сборка из исходников

Сначала клонируйте репозиторий и соберите верификатор:

```sh
git clone <repository-url> gramvanity
cd gramvanity
go build -o verify-go/w5addr ./verify-go     # верификатор на tonutils-go (w5addr.exe на Windows)
```

Затем соберите поиск командами для нужной платформы (Linux / Windows).

Верификатор необязателен. Если его нет, программа всё равно работает, но хиты помечаются как
непроверенные, и использовать их не следует.

### Linux (Ubuntu и подобные)

```sh
sudo apt install build-essential ocl-icd-opencl-dev clinfo
clinfo -l                 # здесь должна быть видна ваша видеокарта
cd opencl
make
```

Среды выполнения OpenCL: драйверы NVIDIA уже включают OpenCL; AMD использует ROCm OpenCL; для
Intel установите `intel-opencl-icd`.

### Windows

Установите [MSYS2](https://www.msys2.org/), откройте оболочку **MSYS2 UCRT64**, затем:

```sh
pacman -S --needed make mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-opencl-icd mingw-w64-ucrt-x86_64-opencl-headers
cd /c/path/to/gramvanity/opencl
make
```

С этого момента запускайте `./gramvanity` в той же оболочке. Драйвер GPU уже содержит OpenCL,
поэтому больше ничего устанавливать не нужно.

После сборки все дальнейшие команды в этом руководстве выполняются из папки `opencl/`.

## Первый запуск

Из папки `opencl/`:

```sh
./gramvanity --list-devices                               # показать GPU, которые видит OpenCL
./gramvanity --mode bip39-12 --bench 60                   # тест скорости на 1 минуту
./gramvanity --mode bip39-12 --bench 60 --power 100       # то же на полной скорости
```

`--bench` только измеряет скорость; он ничего не находит. Первые 10–20 секунд также используются
для подбора размера пакета и длины ядра под вашу видеокарту.

По умолчанию программа использует **65%** времени GPU/CPU (`--power 65`). Так компьютер остаётся
удобным, а вентиляторы — тихими. Используйте `--power 100`, если нужна максимальная скорость.

## Найдите свой адрес

```sh
# адрес заканчивается на HELLO (перед ним — любая строчная буква или _)
./gramvanity --suffix '[a-z_]HELLO' --mode bip39-12
```

Без `--mode` используется `tg-wallet` (Telegram Wallet, 24 слова и активация). В примере выше
указан `bip39-12`, который Tonkeeper и My Wallet импортируют напрямую.

По умолчанию запуск останавливается после первого сохранённого хита (`--count 1` на цель).
Передайте `--count N`, чтобы собрать несколько адресов для одного шаблона, и `--all-patterns`,
чтобы применять счётчик к каждому варианту шаблона цели (см. «Несколько адресов за один запуск»).

Во время работы вы увидите:

- длинную строку каждые 30 секунд: скорость, насколько далеко продвинулся поиск, сколько хитов
  найдено и насколько вероятен хит к этому моменту;
- однократную оценку примерно через четыре секунды после старта: среднее ожидание для каждой цели
  и для первого хита по любой цели. Прочитайте её перед запуском, который может длиться дни.

Хит сохраняется в файл; seed-фраза никогда не печатается в терминал. По умолчанию hit-файл хранит
ключ поиска и индекс, поэтому фразу можно восстановить позже через `--reveal` или `--derive` (при
`--random` сама фраза находится в файле). Программа также заново выводит ключ на CPU и просит
независимый верификатор (если он установлен) подтвердить адрес, прежде чем сообщить о хите.

## Как писать шаблон

- Простой текст совпадает точно, с учётом регистра: `--suffix HELLO` ищет `…HELLO`, а не `…hello`.
- `[...]` означает «один символ из этого списка». Работают диапазоны: `[a-z]` — любая строчная
  буква, `[0-9A-F]` — шестнадцатеричная цифра. Значит, `[a-z_]HELLO` — «строчная буква или _,
  затем HELLO».
- `--prefix` совпадает с началом адреса сразу после двухсимвольного тега формы (`UQ` или
  `EQ`/`0Q`/`kQ` в зависимости от опций).
- `--suffix` совпадает с концом адреса.
- `--ignore-case` позволяет найденному адресу использовать любой регистр; полезно, когда окончание
  должно выглядеть красиво, а не быть конкретным написанием.
- Если у цели есть и префикс, и суффикс, адрес должен удовлетворять **обоим**. Альтернативы внутри
  одного списка объединяются через «или»: можно повторять `--suffix` или разделять значения
  запятыми.
- `--match or` ослабляет это правило: достаточно одной группы, поэтому
  `--prefix MOON --suffix 777 --match or` находит адреса, которые начинаются с MOON **или**
  заканчиваются на 777. Опция работает глобально (до первой `--target`) и внутри цели, где
  переопределяет глобальное значение.
- В адресах используются только `A-Z a-z 0-9 - _`. Всегда берите шаблоны с `[...]` в кавычки,
  иначе оболочка может попытаться их раскрыть.

Примеры:

```sh
./gramvanity --suffix '777' --mode bip39-12
./gramvanity --suffix '[Hh]ELLO' --mode bip39-12          # HELLO или hELLO
./gramvanity --prefix MOON --suffix '777' --mode bip39-12 # начинается с MOON, заканчивается на 777
./gramvanity --suffix 'HELLO,MOON' --mode bip39-12        # любое из окончаний
./gramvanity --prefix MOON --suffix '777' --match or --mode bip39-12 # MOON в начале или 777 в конце
```

## Сколько времени это занимает

Время поиска растёт примерно в 64 раза на каждый дополнительный фиксированный символ. Таблица
предполагает около 681 000 фраз в секунду — это полная скорость (`--power 100`); значение по
умолчанию `--power 65` добавляет к этим временам около 50%.

| Окончание | Среднее время |
|---|---|
| 4 символа | ~25 секунд |
| 5 символов (`HELLO`) | ~26 минут |
| `[a-z_]` + 5 символов | ~12 часов |
| 6 символов | ~1,2 дня |
| 7 символов | ~2,5 месяца |

Это средние значения, а не сроки. Результат случаен: половина запусков завершается за 0,7×
среднего, 90% — за 2,3×, 99% — за 4,6×. Остановка и перезапуск ничего не теряют.

Для справки, на NVIDIA RTX 4070 Ti Super с Ryzen 7 7800X3D под Windows при `--power 100`: около
681 000 фраз в секунду для `bip39-12` и 675 000 для `tg-wallet`. Один PBKDF2 достигает примерно
696 000, поэтому поиск ограничен PBKDF2, а не проверкой адресов.

Практические советы:

- Сначала решите длину, затем точные символы.
- Скобки нужны для покрытия вариантов написания (`[Hh]ELLO`), а не для удешевления поиска — они
  добавляют символ к стоимости.
- Избегайте окончаний из одного-двух символов для кошелька, которым будете пользоваться: они
  достаточно дешёвы, чтобы кто-то другой нашёл другую фразу с таким же окончанием (address
  poisoning).
- Пять фиксированных символов — разумный минимум; шесть или семь делают окончание практически
  уникальным.

## Несколько адресов за один запуск

Каждый блок поиска начинается с `--target [NAME]`. Всё после него относится к этой цели до
следующего `--target`:

```sh
./gramvanity --mode bip39-12 \
  --target HELLO --suffix '[a-z_]HELLO' --count 1 \
  --target MOON  --prefix MOON --suffix '777' --count 2 \
  --target SHORT --prefix '[A-Z]' --suffix 'X'
```

Правила простыми словами:

- Без `--target` у запуска одна безымянная цель — обычный случай.
- Цель без имени называется `t1`, `t2`, … в порядке появления. Если имя повторяется, второе
  становится `A2`, затем `A3` и так далее.
- Имя цели появляется в именах hit-файлов. Кириллические имена транслитерируются в ASCII-id
  (`--target Паша` пишет `hit-Pasha-…`), а исходное имя сохраняется как метка в отчётах и
  checkpoint. Явные id могут содержать только буквы, цифры, `-` и `_`.
- Фиксированного ограничения на число целей нет: список целей растёт по мере необходимости и
  ограничен только памятью.
- `--count N` означает «остановить эту цель после N хитов». По умолчанию `1` для каждой цели,
  включая все цели многопоточного запуска; используйте больший `--count`, чтобы собрать несколько
  адресов для одного шаблона.
- `--all-patterns` переносит счётчик с цели на её варианты шаблона: `--count N` применяется к
  каждому префиксу и каждому окончанию цели, и поиск идёт, пока у каждого варианта не будет N
  хитов. Например, `--target PASHA --suffix '[_-]Pasha' --suffix '[_-]PASHA' --count 1
  --all-patterns` находит один адрес на вариант вместо остановки на первом. Хит засчитывается
  каждому шаблону, которому он соответствует, а хиты, не заполняющие ни один ещё не заполненный
  вариант, сообщаются, но не сохраняются. Флаг работает и как глобальное значение по умолчанию, и
  сохраняется в checkpoint (поэтому возобновлённое задание его сохраняет, а добавить его позже
  можно через `--resume ... --all-patterns`).
- Опции, записанные **до** первого `--target`, являются значениями по умолчанию. Та же опция
  внутри цели переопределяет её только для этой цели.
- `--match and|or` выбирает, как комбинируются две группы цели: `and` (по умолчанию) требует один
  подходящий префикс и один подходящий суффикс; `or` принимает адрес, удовлетворяющий любой группе
  отдельно.
- `--mode`, `--form` и `--net` глобальны: каждая цель запуска использует один и тот же формат
  кошелька.

Когда один адрес подходит нескольким целям, он сохраняется один раз, обе цели засчитывают хит, а
имя файла перечисляет их все: `hit-A+B-<index>.txt`. Если две цели пишут в разные папки `--out`,
каждая папка получает свою копию. Если они используют одну папку, файл записывается один раз.

Цель, достигшая своего `--count`, пропускается; остальные цели продолжают поиск. Запуск
останавливается, когда каждая цель достигла своего счётчика (обычное завершение, поскольку у
каждой цели по умолчанию есть лимит), когда вы его останавливаете или когда заканчивается
детерминированный диапазон фиксированного размера.

## Куда попадают файлы

У каждого запуска своя папка. По умолчанию это `results/job-<timestamp>/` в репозитории
(`../results/job-<timestamp>/`, если запускать из `opencl/`):

```text
job-20261028-101500/                       # внутри results/
  hit-HELLO-123456.txt                     # один файл на хит
  hit-MOON+SHORT-654321.txt                # адрес, подошедший двум целям
  stop-bip39-12-idx1234567-20261028-104500.txt
  job.checkpoint                           # сохранённое состояние поиска (редактируемый текст)
```

`--out DIR` до первой цели выбирает папку самостоятельно. Внутри цели `--out` меняет только то,
куда пишутся хиты этой цели.

- **Hit-файл** — адрес, публичный ключ и то, что было проверено. По умолчанию фраза намеренно
  **не** записывается: файл содержит ключ поиска и индекс, а фразу вы восстанавливаете через
  `--reveal` или `--derive`. При `--random` файл содержит саму фразу, потому что ключа поиска для
  воспроизведения нет.
- **Stop-файл** — записывается в конце каждой сессии (Ctrl+C, закрытие окна, завершение диапазона,
  достижение всех счётчиков). Он содержит статистику, список hit-файлов и точную команду для
  продолжения.
- **Checkpoint** — сохранённое состояние. Держите его в секрете: он содержит ключ поиска, который
  может воссоздать каждую фразу, которую когда-либо создаст задание.

## Форматы кошельков (`--mode`)

| Режим | Фраза | Импортируется в | Скорость |
|---|---|---|---|
| `bip39-12` | 12 слов, BIP39 | Tonkeeper, My Wallet | полная |
| `bip39-24` | 24 слова, BIP39 | Tonkeeper, My Wallet | примерно та же |
| `ton-24` | 24 слова, стандарт TON | любой кошелёк TON | ~100× медленнее |
| `tg-wallet` | 24 слова = две половины BIP39-12 | Telegram Wallet, после активации | как `bip39-12` |

По умолчанию адрес — это кошелёк W5 (v5r1) в mainnet, workchain 0, subwallet 0, а формат фразы —
`tg-wallet`. `--form eq` показывает тот же кошелёк в bounceable-форме `EQ…` вместо `UQ…`.

`ton-24` гораздо медленнее и редко нужен для нового кошелька. Используйте его только если фраза
должна быть стандартной мнемоникой TON.

## Telegram Wallet

В режиме `tg-wallet` фраза состоит из 24 слов, но это **не** одна 24-словная фраза BIP39. Это две
независимые 12-словные фразы:

- слова 1–12 (*якорная* половина) определяют адрес и являются половиной, по которой идёт поиск;
- слова 13–24 (*подписывающая* половина) становятся ключом, которым подписывает Telegram Wallet.

Новый адрес существует только на бумаге: на цепи пока ничего не развёрнуто. Прежде чем Telegram
Wallet примет фразу, кошелёк нужно создать и переключить на подписывающий ключ одним сообщением.
Входящий в комплект Go-верификатор делает именно это:

```sh
../verify-go/w5addr activate --phrase "w1 … w24" --check    # адрес, баланс, состояние
../verify-go/w5addr activate --phrase "w1 … w24" --send     # deploy + rotate (нужно >= 0.02 GRAM)
```

На Windows используйте `..\verify-go\w5addr.exe`. Сначала пополните адрес (0,05–0,1 TON —
комфортно), дождитесь, пока `--check` увидит баланс, затем отправляйте. В testnet используйте
`--net testnet` и получите бесплатный GRAM у
[https://t.me/testgiver_ton_bot](https://t.me/testgiver_ton_bot).

Полные подробности, включая точную структуру сообщения, шаги импорта и необязательную смену
фразы: [docs/tg-wallet.ru.md](docs/tg-wallet.ru.md).

## Остановка, продолжение и повтор

Поиски **детерминированы и возобновляемы по умолчанию**. Каждое новое задание получает случайный
секретный 32-байтовый ключ поиска, и кандидат с номером `index` выводится из этого ключа:

- внутри одного задания кандидат номер 1000 всегда одна и та же фраза, независимо от того, когда вы
  его продолжите;
- поиск можно остановить и продолжить точно с места остановки;
- папку задания можно перенести на другую машину и продолжить там;
- любой хит можно воспроизвести позже по его индексу вместе с checkpoint.

Новое задание всегда получает новый случайный ключ, поэтому две одинаковые команды, запущенные
отдельно, ищут разные фразы. Чтобы продолжить задание, используйте `--resume` с его checkpoint —
новый запуск с `--checkpoint FILE` заменяет этот файл и начинает новую последовательность.

```sh
# детерминированно и возобновляемо; останавливается после первого хита (по умолчанию --count 1)
./gramvanity --mode bip39-12 --suffix '[a-z_]HELLO'

# пять адресов для одного шаблона
./gramvanity --mode bip39-12 --suffix '[a-z_]HELLO' --count 5

# ограниченный диапазон: три миллиона кандидатов, начиная с индекса 1 000 000 000
./gramvanity --mode bip39-12 --suffix '[a-z_]HELLO' --start-offset 1000000000 --tries 3000000

# продолжить позже (stop-файл печатает эту точную команду)
./gramvanity --resume ../results/job-20261028-101500/job.checkpoint

# после хита счётчик по умолчанию исчерпан: запросить ещё один адрес и расширить диапазон
./gramvanity --resume job.checkpoint --count 2 --tries 2000000

# восстановить хит, не имея фразы в файле
./gramvanity --reveal job.checkpoint 123456
./gramvanity --mode bip39-12 --derive <64-hex search key> 123456

# посмотреть checkpoint (секретный ключ не печатается)
./gramvanity --checkpoint-info job.checkpoint
```

`--random` отключает это: каждый кандидат — свежая случайность ОС, ключа поиска нет, и ничего
нельзя возобновить. Используйте его только для коротких разовых поисков. Его нельзя сочетать с
`--start-offset`, `--tries`, `--checkpoint`, `--resume` или `--stop-after`.

Checkpoint сохраняется каждые 30 секунд по умолчанию (`--checkpoint-interval SEC`). Если машина
упадёт, будет повторена максимум работа с момента последнего сохранения. Кандидаты никогда не
пропускаются: сохранённая позиция — это последний индекс, чей адрес был полностью проверен.

При `--resume` все цели восстанавливаются из checkpoint. Вы можете изменить их `--count` и
`--out`; шаблоны, `--ignore-case` и `--match` должны остаться прежними, и это проверяется.
Именованный блок `--target` выбирает цель checkpoint по её id или метке (поэтому `--target Паша`
и `--target Pasha` работают одинаково); блок без имени выбирает следующую неиспользованную цель
по порядку. Повышение счётчика завершённой цели продолжает с текущего общего индекса, поэтому уже
проверенные кандидаты не повторяются.

Checkpoint — обычный UTF-8-текст ("gramvanity-checkpoint" v1): по одному `ключ = значение` на
строку, секции `[target]`, допустимые значения расписаны в комментариях в конце строк, и последняя
строка `checksum` (SHA-256 над остальной частью файла). Откройте его в любом редакторе — файл
объясняет себя сам. Типичные правки — поднять `count` цели, добавить или убрать строку
`suffix`/`prefix` (новые шаблоны применяются с точки продолжения), добавить или убрать целый блок
`[target]`, либо сбросить `next` и счётчики, чтобы пересканировать диапазон. После правки
переподпишите файл (он проверит все поля и пересчитает сумму); `--resume` отказывается читать
файл, чья сумма уже не сходится:

```sh
# поднять count у t1 руками, затем легализовать правку и продолжить
./gramvanity --checkpoint-fix ../results/job-20261028-101500/job.checkpoint
./gramvanity --resume ../results/job-20261028-101500/job.checkpoint
```

Не редактируйте строку `key`: ключ поиска — то, что делает каждый индекс воспроизводимым, и
изменённый ключ молча превращает все дальнейшие хиты в невосстановимые. Строку `checksum`
пересчитывает `--checkpoint-fix`.

## Объединение заданий (`--checkpoint-merge`)

Несколько завершённых или остановленных заданий можно пересобрать в один новый checkpoint, который
содержит только цели, ещё не добравшие свой `--count`:

```sh
# склеить две папки заданий в новую папку задания (по умолчанию: results/job-<UTC-метка>)
./gramvanity --checkpoint-merge --in ../results/job-20261101-090000 --in ../results/job-20261104-174407

# или указать входы и выходную папку явно
./gramvanity --checkpoint-merge --in ../results/job-A/job.checkpoint --in ../results/job-B/job.checkpoint --out ../results/merged
```

`--in` принимает файл checkpoint или папку задания (его `job.checkpoint`); повторите его для
каждого входа. Объединённый файл записывается как `job.checkpoint` в новой папке задания:
`--out DIR` использует эту папку ровно как задана, иначе создаётся новая
`results/job-<UTC-метка>`.

Что объединение сохраняет и что меняет:

- цели, уже добравшие свой `--count`, **отбрасываются**; цели без лимита и невыполненные
  переносятся со своими `hits` и счётчиками по шаблонам, так что `count - hits` остаётся остатком
  работы. Прежние хиты каждой цели остаются восстановимыми только из её исходного checkpoint
  (`--reveal` там, а не в объединённом файле);
- одна и та же цель (то же имя и те же шаблоны) в нескольких входах склеивается в одну по максимуму
  полей; повторно использованное имя с другими шаблонами получает суффикс `-2`, `-3`...;
- объединённое задание — **новое задание**: свежий ключ поиска, позиция начинается с индекса 0,
  счётчики задания обнулены — кандидаты выводятся из ключа, и под новым ключом ещё ничего не
  искали;
- объединённый файл не хранит `job_dir`: при `--resume` его собственная папка и есть папка задания,
  поэтому новые хиты ложатся рядом с объединённым checkpoint. Чтобы разместить его в другом месте,
  добавьте строку `job_dir` вручную и выполните `--checkpoint-fix`.

Все входы должны совпадать по режиму, форме и сети кошелька. Существующий выходной файл
объединение никогда не перезаписывает.

## Безопасность

- Seed-фраза записывается **только** в hit-файлы (или в файл `--dump`, который вы запросили), но
  никогда в терминал. На Linux файлы доступны только вашему пользователю. По умолчанию фразы в
  hit-файле вообще нет (только ключ поиска и индекс); `--random` вместо этого хранит там фразу.
- Держите папку задания в секрете. Checkpoint может воссоздать каждую фразу-кандидат задания.
- Каждый хит проверяется независимо: программа пересчитывает его на CPU и (если установлен)
  верификатор заново выводит адрес по логике импорта самих кошельков. Хит, который не прошёл
  проверку, записывается как `UNVERIFIED HIT, DO NOT USE`.
- Фразы, которые кошельки могли бы прочитать двумя разными способами, намеренно пропускаются,
  потому что разные кошельки показывали бы для них разные адреса.
- Тестовые фразы, напечатанные в исходниках или используемые тестами, — публичные временные фразы.
  Никогда не отправляйте на них средства.
- Перед отправкой реальных денег: импортируйте фразу, выберите W5, сравните адрес и сделайте
  небольшой тестовый перевод туда и обратно. В режиме `tg-wallet` сравните адрес с `--check` или
  обозревателем блоков после активации.
- Затем запишите фразу на бумаге и удалите папку задания.

## Если что-то пошло не так

- `no OpenCL GPU found` — драйвер GPU не предоставляет OpenCL. Проверьте `clinfo -l` на Linux и
  установите пакет OpenCL от производителя GPU.
- `OpenCL kernel build failed` — пожалуйста, сообщите полный текст ошибки.
- `SELF-TEST FAILED` — GPU или драйвер вычисляют неправильные результаты. Не ищите на этом
  устройстве.
- `GRAMVANITY_DEBUG=1` печатает внутренние детали подбора каждого пакета.
- Долгие запуски на Windows: держите окно открытым и отключите сон в настройках питания.

Инструкции по сборке и внутреннее устройство: [opencl/README.ru.md](opencl/README.ru.md).

- `results/` — создаётся во время работы; одна папка `job-<timestamp>/` на запуск, игнорируется
  Git.
