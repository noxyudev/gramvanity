# gramvanity — сборка и внутреннее устройство

> Язык: [English](README.md) | **Русский**

В этой папке находится сама программа поиска: C host в `src/` и OpenCL-ядра. Это документ о
разработке и сборке. Всё об **использовании** программы — установка, шаблоны, цели, режимы
кошельков, продолжение и безопасность — находится в [основном README](../README.ru.md);
руководство по Telegram Wallet — [../docs/tg-wallet.ru.md](../docs/tg-wallet.ru.md), а карта
модулей `src/` — [../docs/architecture.ru.md](../docs/architecture.ru.md).

Одним предложением: программа пробует случайные seed-фразы, превращает каждую в адрес кошелька
TON и сохраняет фразы, адрес которых соответствует запрошенному шаблону. Тяжёлая часть (вывод
ключей) выполняется на GPU; проверки — на CPU.

> **Откуда это взялось:** оригинальный проект —
> [necrovolt/seedvanity](https://github.com/necrovolt/seedvanity) от
> [miutalk](https://t.me/miutalk) и [Vibes 18+](https://t.me/vibes). Этот форк поддерживает
> [нокси](https://t.me/pauper): поддержка macOS удалена (только OpenCL), а форк добавляет
> несколько целей на запуск, одну папку задания на запуск и пригодный для правки руками текстовый
> формат checkpoint.

## Состояние

- Проверено на корректность на NVIDIA RTX 4070 Ti Super под Windows: тысячи фраз перекрёстно
  сверены с независимой реализацией tonutils-go.
- Собирается и линкуется для Linux (x86_64, arm64) и Windows (x86_64).
- Пока не запускалось на оборудовании AMD.
- При каждом старте программа сравнивает результаты GPU с CPU и отказывается искать при
  расхождении.

Отзывы и бенчмарки приветствуются.

## Сборка

Требования: компилятор C и OpenCL SDK/ICD loader (см. шаги для каждой платформы). Среду выполнения
OpenCL обычно предоставляет сам драйвер GPU. Сборка необязательного Go-верификатора описана в
[основном README](../README.ru.md) (`go build -o verify-go/w5addr ./verify-go` из корня
репозитория).

### Linux (Ubuntu и подобные)

```sh
sudo apt install build-essential ocl-icd-opencl-dev clinfo
clinfo -l                 # GPU должен быть виден здесь
cd opencl
make
```

Среды выполнения OpenCL: проприетарный драйвер NVIDIA уже включает OpenCL; AMD использует ROCm
OpenCL; для Intel установите `sudo apt install intel-opencl-icd`.

### Windows

Установите [MSYS2](https://www.msys2.org/), откройте оболочку **MSYS2 UCRT64** и выполните:

```sh
pacman -S --needed make mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-opencl-icd mingw-w64-ucrt-x86_64-opencl-headers
cd /c/path/to/gramvanity/opencl
make
```

Если линковка падает с `undefined reference to BCryptGenRandom`, Makefile не определил Windows
(`OS` не равен `Windows_NT`, что бывает, когда MSYS2 запускают из другой оболочки, а не открывают
обычным образом). Передайте библиотеки Windows явно:

```sh
make LIBS="-lOpenCL -lbcrypt -static-libgcc"
```

С этого момента `gramvanity.exe` запускается как из оболочки MSYS2, так и из обычной командной
строки.

### Цели Make

| Цель | Что делает |
|---|---|
| `make` | собирает `gramvanity` (`gramvanity.exe` на Windows) из `src/` + `embedded.h` |
| `make embed` | перегенерирует `embedded.h` (см. ниже) |
| `make clean` | удаляет собранный бинарник |

`embedded.h` (ядра + словарь) генерируется и коммитится, поэтому для сборки нужен только
компилятор C. После редактирования `kernel.cl`, `ed25519_gpu.cl`, `sha512_consts.h` или
`english.txt` запустите `make embed` (нужен `python3`, или `python` на Windows) и закоммитьте
результат — сборка никогда не читает исходные файлы напрямую.

### Быстрая проверка

```sh
./gramvanity --list-devices                              # GPU, видимые OpenCL
./gramvanity --mode bip39-12 --bench 60                  # тест скорости на минуту, ничего не находит
```

Для реального поиска — шаблоны, цели, продолжение — следуйте [основному README](../README.ru.md).

## Тесты

```sh
./gramvanity --selftest-det   # детерминированный поиск и unit-тесты целей, GPU не нужен
sh tests/test_det.sh          # сквозные тесты на GPU: остановка/продолжение/крэш/хит/повтор/цели
```

`--selftest-det` проверяет детерминированную энтропию и разделение режимов (включая домен
подписи tg-wallet), контрольные суммы BIP39 у генерируемых кандидатов в обеих половинах
tg-wallet, учёт индексов/диапазонов (без пропусков, без переполнения, обработка переполнения
2^64), round-trip checkpoint с записями целей и отклонение повреждённых, усечённых и чужих
бинарных файлов, сценарии ручной правки с `--checkpoint-fix`, слияние checkpoint (отбрасывание
выполненных целей, склейка одинаковых по максимуму, переименование, свежий ключ), граничные
случаи кавычек, сопоставление целей AND/OR, `--ignore-case`, разрешение имён и
кириллические/CP1251-метки.

`tests/test_det.sh` добавляет сквозные сценарии на GPU: stop-after → resume → завершение;
проверенный хит → ключ+индекс → повтор с `--derive`/`--reveal`; tg-wallet в mainnet и testnet;
повреждённые и конфликтующие checkpoint; прерывание `ton-24`; хиты с несколькими шаблонами и
целями с счётчиками и папками вывода на цель; продолжение с увеличенными счётчиками; сборка
заданий (`--checkpoint-merge`); кириллические метки, их транслитерированные имена файлов и
продолжение по метке.

## Справочник командной строки

Все опции в одном месте (программа объясняет каждую в выводе `--help` и в сообщении об
использовании):

```text
--mode bip39-12|bip39-24|ton-24|tg-wallet    --net mainnet|testnet (tg-wallet)
--form uq|eq          --ignore-case          --lang en|ru
--target [NAME]                   (начинает блок цели; можно повторять)
--prefix PATTERN                  (на цель/по умолчанию; можно повторять / через запятую)
--suffix PATTERN                  (на цель/по умолчанию; можно повторять / через запятую)
--count N                         (на цель/по умолчанию)
--out DIR                         (папка задания до первой цели; папка хитов внутри цели)
--threads N                       --power N             --device N
--list-devices                    --bench SEC           --no-verify
--dump N FILE
--start-offset N                  --tries N             --checkpoint FILE
--resume FILE                     --checkpoint-interval SEC
--stop-after N                    --checkpoint-info FILE
--checkpoint-fix FILE             --checkpoint-merge --in FILE|DIR [--in ...] [--out DIR]
--random                          --derive KEYHEX INDEX
--reveal CHECKPOINT INDEX         --selftest-det
--help
```

- `--threads N` — потоки CPU для проверки адресов и верификации хитов (по умолчанию: все
  логические CPU).
- `--power N` — держать GPU и CPU занятыми N% времени (по умолчанию 65, `100` = без ограничения).
- `--device N` — использовать GPU номер N из `--list-devices`.
- `--lang en|ru` — язык понятных человеку сообщений (по умолчанию `en`; также можно задать через
  `GRAMVANITY_LANG`).
- `--no-verify` — пропустить внешний верификатор. Пересчёт каждого хита на CPU всё равно
  выполняется.
- `--dump N FILE` — записать N свежих фраз и их адреса в FILE (JSON lines) и выйти; полезно для
  тестирования, не для поиска.
- `--checkpoint-fix FILE` — проверить отредактированный вручную checkpoint и пересчитать подпись.
- `--checkpoint-merge` — собрать новый checkpoint из невыполненных целей одного или нескольких
  checkpoint; каждый `--in` — файл checkpoint или папка задания, `--out` — новая папка задания
  (по умолчанию `results/job-<UTC-метка>`). Выполненные цели отбрасываются; результат — новое
  задание со свежим ключом, подробнее — «Объединение заданий» в основном README.
- `GRAMVANITY_DEBUG=1` — переменная окружения; печатает подбор размера пакета и длины ядра для
  каждого цикла.

## Устранение неполадок

- `no OpenCL GPU found` — драйвер не предоставляет OpenCL. На Linux проверьте `clinfo -l`;
  установите пакет OpenCL для вашего производителя GPU.
- `OpenCL kernel build failed` — пожалуйста, сообщите полный текст ошибки.
- `SELF-TEST FAILED` — GPU или его драйвер дают неверные результаты. Не ищите на этом устройстве.
- `undefined reference to BCryptGenRandom` — см. раздел сборки для Windows выше.
- Долгие запуски на Windows: держите окно открытым и отключите сон в настройках питания.

## Под капотом (необязательное чтение)

Этот раздел для любопытных; для использования программы он не нужен.

**Что где выполняется.** GPU делает дорогую работу по каждому кандидату: PBKDF2-HMAC-SHA512
(`kernel.cl`; 2048 раундов для BIP39, 100 000 для стандартной мнемоники TON), путь вывода ключа
BIP39 `m/44'/607'/0'` и публичный ключ Ed25519 (`ed25519_gpu.cl`). CPU превращает публичный ключ
в адрес кошелька (W5 v5r1 или WalletTg в режиме `tg-wallet`), проверяет шаблоны каждой цели на
всех потоках и заново выводит каждый хит независимо с помощью
[ed25519-donna](https://github.com/floodyberry/ed25519-donna).

**Windows и длинные ядра.** Windows перезапускает драйвер GPU, когда одно ядро работает дольше
примерно двух секунд (TDR). Поэтому PBKDF2 разбит на запуски по `chunk` итераций, а состояние
хранится в памяти GPU между ними; каждый запуск нацелен примерно на 0,25 секунды. Стоимость
итерации оценивается консервативно (берётся большее из профилированного времени ядра и общего
времени цикла) и медленно затухает, потому что некоторые драйверы сообщают неверное время
профилирования или поздно сигналят события.

**Пакеты.** Пакет начинается с 16 384 фраз и растёт до 1 000 000, пока пакет остаётся коротким.
GPU работает над следующим пакетом, пока CPU завершает предыдущий (двойная буферизация).

**Ограничение мощности.** `--power N` (по умолчанию 65, `100` = без ограничения) регулирует весь
конвейер через рабочий цикл: после каждого пакета цикл спит `busy * (100 - N) / N` секунд. Ниже
100% следующий пакет не ставится в очередь заранее, иначе GPU продолжал бы работать во время
паузы. Пауза нарезана на срезы по 100 мс, поэтому Ctrl+C остаётся отзывчивым.

**Ed25519 на GPU.** Закрытый хэш SHA-512 перекодируется в 64 знаковые цифры по основанию 16.
Публичный ключ — сумма `d[i]`, умноженных на предвычисленную таблицу `[j*16^i]B` из 512 аффинных
точек, построенную при старте. Каждая цифра стоит одного смешанного сложения (8 умножений в поле),
без удвоений; финальный аффинный `y` стоит одной инверсии Ферма. Поле использует раскладку
radix-2^25.5 из ref10 с десятью знаковыми 32-битными лимбами, поэтому каждое произведение
помещается в 64-битное целое (раскладка 5×51 бит, используемая на CPU, потребовала бы
64×64-битных произведений). На RTX 4070 Ti Super один ключ стоит около 0,03 µs времени GPU —
примерно 2% работы PBKDF2, поэтому поиск остаётся ограниченным PBKDF2.

**Проверка адресов.** С Ed25519 на GPU CPU только хэширует StateInit кошелька (SHA-256), строит
адрес и проверяет группы префикса/окончания каждой цели для каждого кандидата. Публичные ключи
читаются вместе с приватными и используются как есть. Хит всё равно заново выводится с нуля на
CPU (PBKDF2 HMAC-SHA512 Monocypher и SLIP-10, Ed25519 ed25519-donna), должен совпасть с
результатом GPU и затем перепроверяется Go-верификатором.

**Формат checkpoint.** Обычный UTF-8-текст ("gramvanity-checkpoint" v1): по одному
`ключ = значение` на строку, секции `[target]`, перечисления значений в комментариях в конце строк
и последняя строка `checksum` — SHA-256 над всеми остальными строками файла (CR-байты
игнорируются), поэтому повреждение или ручная правка в любом месте будут пойманы. Он хранит папку
задания, глобальные флаги, id/метки/шаблоны/счётчики/хиты/папки вывода каждой цели, курсоры и
секретный ключ поиска; записывается атомарно (временный файл, сброс, переименование), поэтому крэш
не может оставить недописанный файл. Файл создан для того, чтобы его читали и правили руками в
любом редакторе: поднять `count`, поменять шаблоны, добавить или убрать блок `[target]` — после
правки выполните `gramvanity --checkpoint-fix FILE`, чтобы проверить поля и пересчитать подпись
(`--resume` отказывается читать файл с несовпадающей суммой). Необязательные строки имеют значения
по умолчанию, поэтому новый блок `[target]` может состоять из `name` и одного `suffix`; пустые
`job_dir` и `out` не пишутся вовсе (объединённый checkpoint на это опирается: его собственная
папка становится папкой задания).
Неизвестные и повторные ключи — ошибки, поэтому опечатка не может молча изменить состояние поиска.
Индексы обрабатываются строго по порядку `[start, end)`, а сохранённая позиция — последний
**подтверждённый** индекс: всё ниже него уже проверено по адресу, поэтому продолженный запуск
начинается ровно там, без пропусков, повторяя максимум работу с последнего автосохранения. Вся
арифметика проверяется на переполнение. В режиме `tg-wallet` подписывающая половина хита выводится
из того же ключа поиска с собственным доменным тегом, поэтому `--derive`, `--reveal` и `--resume`
всегда воспроизводят точные 24 слова. Держите checkpoint, hit- и stop-файлы в секрете: тот, у кого
есть ключ поиска, может вывести каждую фразу-кандидат задания.

**Стартовый self-test.** SHA-256 и тестовый вектор BIP39 PBKDF2 на CPU; GPU против CPU для PBKDF2
и SLIP-10 (ключи длиннее 128 байт, принудительные границы чанков); Ed25519 на GPU против CPU
(вектор RFC 8032, случайные ключи и раскладка TON stage-2); адреса W5 и WalletTg фиксированных
тестовых фраз против эталонных векторов, изначально созданных с @ton/ton (обе сети); контрольные
суммы BIP39.

**Файлы.** Host-программа живёт в `src/` как сосредоточенные модули (`platform`, `options`,
`pattern`, `crypto`, `addresses`, `detsearch`, `gpu`, `stats`, `checkpoint`, `hits`, `search`,
`selftest`, `main`); карта модулей, владение общим состоянием и дисциплина блокировок описаны в
[../docs/architecture.ru.md](../docs/architecture.ru.md). OpenCL-ядра лежат рядом: `kernel.cl`
(PBKDF2/SLIP-10) и `ed25519_gpu.cl` (Ed25519). `embedded.h` содержит исходники ядер и словарь
BIP-0039. `third_party/monocypher/` — Monocypher (CC0 или BSD с 2 пунктами, см. `LICENCE.md` и
`VERSION`). `third_party/ed25519/` — ed25519-donna (общественное достояние, см. её `README.md`);
она используется для пересчёта каждого хита на CPU и для таблицы фиксированной базы в GPU-ядре
(`ed25519_gpu_table` в `ed25519_fast.c`).

**Секретные файлы.** Checkpoint, hit- и stop-файлы создаются доступными только владельцу: режим
`0600` на Linux; на Windows они наследуют ACL профиля пользователя, поэтому держите папку
результатов вне общих мест.
